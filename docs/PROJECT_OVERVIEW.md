## 1. Огляд проєкту та мета

Інвертор **Datouboss DT-1218** (12V, 1800W) для коректної роботи з літієвими акумуляторами (LiFePO4) у режимі BMS вимагає прямого протокольного зв'язку через порт `RS485-2` за протоколом **Growatt (режим A17 = Li, протокол GRO)**. При відсутності зв'язку інвертор сигналізує критичну помилку `Error 63` і припиняє або обмежує заряд/розряд.

**JK-BMS** (модель 4S, Bluetooth MAC: `AA:BB:CC:DD:EE:FF`) забезпечує захист та балансування комірок LiFePO4, але має лише інтерфейс BLE (або пропрієтарний TTL UART).

### Ключові завдання контролера:
1. **Бездротовий збір даних**: Отримання телеметрії з JK-BMS через BLE (напруги комірок 1–4, струм, заряд SOC, температура MOS, стан ключів).
2. **Емуляція Growatt BMS**: Формування відповідей протоколу Growatt BMS на апаратному UART1 (RS485-2) для зняття помилки 63 та передачі лімітів струму/напруги заряду в інвертор.
3. **Моніторинг та керування інвертором**: Опитування робочих параметрів інвертора (напруга мережі, напруга шини 400V, струми заряду A12/A14, температури) та надання можливості їх зміни через UART2 (RS485-1, Modbus RTU).
4. **Автономний Web-інтерфейс**: Автономна панель керування безпосередньо в браузері (`http://<ESP32_IP>`) з оновленням у реальному часі через Server-Sent Events (SSE).
5. **Публікація в MQTT**: Відправка всіх параметрів на брокер Mosquitto (`192.168.31.121:1883`) з префіксом `datouboss/`.

## 2. Апаратна архітектура та розпіновка

### Компоненти системи:
- **Мікроконтролер**: ESP32-WROOM-32 (NodeMCU-32S / ESP32 DevKit v1, Chip rev 3.1).
- **Модуль RS485 #1 (Growatt BMS)**: TTL-to-RS485 з автоматичним контролем напрямку (MAX485 / MAX13487 або плата з автоперемиканням TX/RX).
- **Модуль RS485 #2 (Datouboss Modbus)**: TTL-to-RS485 для опитування телеметрії інвертора.
- **Блок живлення**: DC-DC понижувач 12V -> 5V (2A) від шини акумулятора.

```
                    +-------------------------------------------------+
                    |       ESP32 WROOM-32 (<ESP32_IP>)           |
                    |                                                 |
[JK-BMS 4S] <-------+ BLE 2.4 GHz                                     |
AA:BB:CC:DD:EE:FF   |                                                 |
                    |   UART1 (9600, 8N1)      [RS485 Transceiver 1]  |
                    |   GPIO17 (RX) <--------> RO                     |
                    |   GPIO16 (TX) <--------> DI                     |
                    |                          A / B ----------------> [Datouboss RS485-2]
                    |                                                  (BMS Port, GRO)
                    |   UART2 (9600, 8N1)      [RS485 Transceiver 2]  |
                    |   GPIO27 (RX) <--------> RO                     |
                    |   GPIO14 (TX) <--------> DI                     |
                    |                          A / B ----------------> [Datouboss RS485-1]
                    |                                                  (Monitor/Control)
                    +-------------------------------------------------+
```

### Таблиця підключення виводів ESP32:

| Лінія ESP32 | Призначення | Підключення до модуля | Порт інвертора / Пристрій |
| :--- | :--- | :--- | :--- |
| **GPIO17** | UART1 RX | Модуль RS485 #1 (RO) | Інвертор RS485-2 (BMS Port pin 1/2) |
| **GPIO16** | UART1 TX | Модуль RS485 #1 (DI) | Інвертор RS485-2 (BMS Port pin 1/2) |
| **GPIO27** | UART2 RX | Модуль RS485 #2 (RO) | Інвертор RS485-1 (Monitor pin 7/8) |
| **GPIO14** | UART2 TX | Модуль RS485 #2 (DI) | Інвертор RS485-1 (Monitor pin 7/8) |
| **5V / VIN** | Живлення | Вихід DC-DC 5V | Загальна лінія 5V |
| **GND** | Загальний мінус | GND модулів RS485 | Загальна шина GND |
| **BLE** | Бездротовий канал | Вбудована антена ESP32 | JK-BMS (MAC: `AA:BB:CC:DD:EE:FF`) |

> [!IMPORTANT]
> Землі (GND) ESP32, модулів RS485 та інвертора обов'язково повинні мати спільну точку з'єднання для запобігання зміщенню логічних рівнів.

## 3. Протоколи зв'язку

### 3.1 JK-BMS BLE (Bluetooth Low Energy)
- **Компонент**: `jk_bms_ble` (зовнішній компонент ESPHome).
- **Частота оновлення**: кожні 5 секунд (прийом 300-байтних кадрів `Cell info frame` та `Settings frame`).
- **Отримувані метрики**:
  - Напруги комірок 1, 2, 3, 4 (точність до 0.001 В).
  - Загальна напруга батареї (`JK Total Voltage`, В).
  - Струм заряду/розряду (`JK Current`, А).
  - Заряд батареї (`JK State of Charge`, %).
  - Температура транзисторів (`JK MOS Temperature`, °C).
  - Дельта напруги комірок (`JK Delta Cell Voltage`, В).
  - Залишковий запас ємності (`JK Remaining Capacity`, А·год).
  - Стан перемикачів заряду, розряду, балансира (`jk_bms_charging`, `jk_bms_discharging`, `jk_bms_balancer`).

### 3.2 Growatt BMS Server (Порт RS485-2 інвертора)
- **Протокол**: Емуляція Growatt BMS (режим `A17 = Li`, протокол `GRO`).
- **Швидкість**: 9600 бод, 8 біт даних, без парності, 1 стоп-біт (8N1).
- **Поведінка**: Інвертор виступає Modbus Master і кожні ~1.5 с опитує 40 регістрів (`Function 0x03, Address 0x0001, Count 0x0028`):
  ```
  Запит:  01 03 00 01 00 28 14 14
  ```
- **Відповідь контролера**: 85 байт даних (`01 03 50 [80 байт даних] [CRC16]`), що містять:
  - Напругу акумулятора (у 0.01 В).
  - Струм (у 0.1 А зі зміщенням 30000).
  - Заряд SOC (%).
  - Максимальну допустиму напругу заряду (14.4 В для 4S LiFePO4).
  - Напругу вимкнення при розряді (11.2 В).
  - Максимальний дозволений струм заряду (налаштовується у Web UI).
  - Максимальний дозволений струм розряду (120 А).
  - Температуру батареї та статус помилок.

### 3.3 Datouboss Modbus RTU Controller (Порт RS485-1 інвертора)
- **Протокол**: Modbus RTU Master (`modbus_controller` ESPHome).
- **Адреса інвертора**: 1.
- **Швидкість**: 9600 бод, 8N1.
- **Інтервал опитування**: кожні 5 секунд.
- **Дроселювання команд**: `command_throttle: 100ms`.

## 5. Усунення помилки 63 (BMS Communication Loss)

### Причина виникнення помилки в заводській або наївній реалізації:
1. Інвертор Datouboss з протоколом GRO дуже суворо контролює таймаут відповіді (~500 мс).
2. Якщо в обробнику кадру виконувати блокуючі затримки (`delay`, `flush()`), повільне логування через UART або важкі виклики `publish_state` на кожен запит інвертора, час відповіді перевищував ліміт.
3. Одночасний прийом важкого 300-байтного кадру BLE від JK-BMS призводив до затримки циклу опитування.

### Впроваджені архітектурні рішення:
- **Zero-Latency Response**: Відповідь на запит інвертора відправляється **миттєво** напряму через апаратний буфер UART FIFO (`this->write_array(resp, sizeof(resp));`) без жодних проміжних обчислень.
- **Видалення блокуючого `flush()`**: Буфер передається контролером апаратно, цикл ESP32 не заморожується на 88 мс.
- **Оптимізований таймаут тиші**: Зменшено з 15 мс до **5 мс** (для швидкості 9600 бод 3.5 символи становлять 3.65 мс).
- **Дроселювання телеметрії**: Оновлення Web UI та логів винесено в окремий таймер (1 раз на 5 секунд), а не на кожен кадр.
- **Захист від переповнення буфера**: Якщо через перешкоди на лінії буфер перевищує 256 байт, він автоматично скидається (`rx_buffer_.clear()`).
- **Збільшений RX буфер**: `rx_buffer_size: 512` у конфігурації UART.

## 6. Мережеві налаштування та надійність

### Відмова від статичного `manual_ip` та перехід на DHCP з фіксацією MAC:
Раніше використовувався `manual_ip: <ESP32_IP>`. На роутерах Xiaomi це викликало проблему:
> Роутер періодично очищав статичні записи з ARP-таблиці (через відсутність регулярних DHCP-запитів оновлення оренди). У результаті пристрій втрачав доступ до мережі, пінг зростав до десятків секунд або повертав `No route to host` / `Host is down`.

**Рішення**:
- З `datouboss.yml` повністю прибрано `manual_ip:`.
- IP-адресу `<ESP32_IP>` закріплено за MAC-адресою пристрою `38:3E:51:6E:4D:50` в налаштуваннях роутера Xiaomi.
- ESP32 працює за повноцінним протоколом DHCP і періодично поновлює оренду, що тримає ARP-кеш роутера завжди актуальним.

### Сторожовий таймер Wi-Fi (Watchdog):
- У конфігурації `wifi:` встановлено:
  ```yaml
  reboot_timeout: 10min
  ```
- Якщо зв'язок із мережею Wi-Fi втрачено довше ніж на 10 хвилин, контролер автоматично виконує повне апаратне перезавантаження.

## 7. Системна діагностика

У прошивку інтегровано спеціалізовані сенсори для моніторингу стабільності мікроконтролера:

| Сенсор | ID | Одиниці | Період | Опис |
| :--- | :--- | :---: | :---: | :--- |
| **Free Heap** | `dt_free_heap` | kB | 30 с | Обсяг доступної оперативної пам'яті RAM (`esp_get_free_heap_size()`) |
| **Reset Reason** | `dt_reset_reason` | текст | 60 с | Причина останнього рестарту (`esp_reset_reason()`) |
| **WiFi Signal** | `dt_wifi_signal` | dBm | 60 с | Рівень сигналу Wi-Fi |
| **Uptime** | `dt_uptime` | с | 30 с | Час безперервної роботи контролера |
| **Growatt Rx/Tx** | `growatt_bms_rx_packets` / `tx` | шт | 5 с | Лічильники прийнятих та надісланих пакетів BMS |
| **Last Request** | `growatt_bms_last_request` | hex | 5 с | Останній отриманий Modbus запит від інвертора |

### Типові причини перезавантаження (`Reset Reason`):
- `Power-on reset` — подача або пересмикування живлення.
- `Software reset digital core` — перезапуск після оновлення прошивки по OTA.
- `Main watch dog reset` — спрацювання сторожового таймера зависання.

## 8. Веб-інтерфейс (Web UI)

Веб-інтерфейс вбудований безпосередньо в прошивку ESPHome через модуль `web_server: version 3`. Використовуються кастомні файли `custom_datouboss.js` та `custom_datouboss.css`.

### Основні розділи інтерфейсу:
1. **Головний статусний рядок (Header)**:
   - Стан живлення (Мережа / Інвертор).
   - Заряд акумулятора (SOC) з JK-BMS.
   - Напруга АКБ.
   - Рівень сигналу Wi-Fi (dBm).
2. **Вкладка «🔋 Акумулятор JK-BMS»**:
   - Напруга 4-х комірок з індивідуальними шкалами та дельтою балансування.
   - Струм заряду/розряду, миттєва потужність.
   - Керування ключами захисту: Заряд (`Charge`), Розряд (`Discharge`), Балансир (`Balance`), Сплячий режим (`Smart Sleep`).
3. **Вкладка «⚡ Інвертор Datouboss»**:
   - Напруга мережі, напруга батареї, напруга шини 400V, вихідна потужність.
   - Температури трансформатора та DC-DC.
   - Інтерактивне встановлення струмів:
     - 🔌 Струм від мережі (A12) — з кнопкою «Застосувати».
     - ☀️ Сонячний / загальний струм (A14) — з кнопкою «Застосувати».
     - 🚀 Загальний ліміт струму (Reg 24) — з кнопкою «Застосувати».
4. **Вкладка «🌉 Growatt BMS Шлюз»**:
   - Лічильники пакетів RX/TX (візуалізація активного обміну кожні 1.5 с).
   - Відображення сирого шістнадцяткового кадру останнього запиту.
5. **Вкладка «ℹ️ Система та діагностика»**:
   - Час безперервної роботи (Uptime).
   - Обсяг вільної пам'яті (Free Heap) у kB.
   - Причина останнього рестарту (Reset Reason).
   - Кнопка примусового перезавантаження контролера.

- Проєкт: `datouboss.yml`
- Віртуальне середовище ESPHome: `esphome`

```bash
# 1. Валідація конфігурації YAML

esphome upload datouboss.yml --device <ESP32_IP>

# 4. Перегляд онлайн-логів через мережу
esphome logs datouboss.yml --device <ESP32_IP>
```
